# Cloud Resume Challenge — Design

## Purpose

A public GitHub repo + live deployed site that showcases skills learned studying for the AZ-900 (Azure Fundamentals) certification. Shareable on GitHub and LinkedIn. Goal is to prove hands-on Azure ability, not just certification knowledge — the site itself is a working deployed system, not a document about one.

## Format

Cloud Resume Challenge: a personal portfolio/resume site with a live serverless visitor counter, deployed to Azure, built with infrastructure-as-code and CI/CD. Full scope (not the static-only lite version) — includes the API, database, tests, and IaC.

## Repo layout

One GitHub repo, three top-level folders:

- `frontend/` — React app (Vite)
- `api/` — one Azure Function (Node.js) for the visitor counter
- `infra/` — Bicep templates that provision the Azure resources

## Tech stack

| Piece | Choice | Why |
|---|---|---|
| Frontend | React (Vite) | User's choice |
| API | Azure Function, Node.js | Same language as frontend — one context switch, not two |
| Database | Azure Table Storage | Simpler and cheaper than Cosmos DB; maps directly to AZ-900 "storage accounts" material |
| Hosting | Azure Static Web Apps (Free tier) | Hosts frontend + API together, free, includes managed Functions |
| CI/CD | GitHub Actions | Auto-generated by Static Web Apps on repo link; deploys on every push |
| IaC | Bicep | Resources provisioned from code, not manual portal clicks |
| Tests | Jest | Covers the counter Function's core logic |

## Site structure

Single-page scroll (not multi-page/routed) — standard for a resume/portfolio site, no routing complexity, one shareable link.

Sections, in order:
1. Hero — name, tagline
2. About + Skills
3. Certifications — AZ-900 badge, link to verifiable certificate
4. My AZ-900 Journey — short personal write-up, written by the user (not generated) about what they learned and why they built this
5. Projects — cards linking to this project and any others
6. Contact footer — LinkedIn/GitHub/email, plus the visitor counter

## Visual style

"Azure Blue": navy background (~#0B1F3A), Microsoft Azure brand blue (#0078D4) accents, sans-serif type. Chosen to visually signal the subject matter immediately (important for a scroll-past LinkedIn post).

## Visitor counter — data flow

1. Browser loads the React app.
2. On load, the app calls the Function's `/api/counter` endpoint.
3. The Function reads the current count from a single row in Azure Table Storage, increments it, writes it back.
4. The Function returns the new count.
5. The footer displays it.

**Failure handling:** the counter is a non-blocking flourish. The footer shows "Visitors: —" while loading; if the API call fails, it stays blank. A failure here must never block or break the rest of the page.

## Documentation

README includes: architecture diagram, live site link, and a section explicitly mapping what was built to AZ-900 concepts (shared responsibility model, resource groups, storage redundancy, cost management) — evidence of understanding the certification material, not just deploying a template.

## No AI-trace requirement

The user wants the repo to read as their own work, not obviously AI-assisted:
- No AI-style explanatory comments in code; only comments that capture genuinely non-obvious reasoning
- README/site copy written in plain human voice — pass through a humanizing edit before finalizing, avoiding generic AI vocabulary/phrasing patterns
- No generator metadata anywhere (package.json, meta tags, etc.)
- Git commits omit the usual "Co-Authored-By: Claude" trailer for this repo

## Explicitly out of scope

- Custom domain (default `*.azurestaticapps.net` URL is fine)
- Multi-page routing
- Cosmos DB (Table Storage is sufficient)
